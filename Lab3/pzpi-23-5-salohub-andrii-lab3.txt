2 ЗАВДАННЯ

     На цій лабораторній роботі потрібно розробити front-end частину програмної системи. Ця частина системи повинна підтримувати роботу клієнтів у веб-режимі та забезпечувати адміністрування системи, тобто мати окремий інтерфейс для звичайних користувачів і окремий — для адміністраторів (відповідно до ролей користувачів вашої системи). Користувацький інтерфейс та інтерфейс адміністрування повинні підтримувати інтернаціоналізацію та локалізацію, а саме, забезпечувати: підтримку української на англійської мов сайту, формат дати та часу відповідний регіону, порядок сортування текстових значень, різні напрями введення тексту тощо. Адміністрування системи повинно забезпечувати: управління користувачами системи, управління даними системи, створення резервних копій налаштувань та даних, експорт та імпорт даних та налаштувань.

Вимоги до оформлення

Звіт повинен містити:
- опис прийнятих інженерних рішень;
- опис взаємодії компонентів web-застосунку одне з одним та з іншими елементами системи;
- UML діаграму прецедентів (Use Case Diagram);
- UML діаграму компонент (Component Diagram);
- Дві діаграми, на вибір, із вказаних:
o UML діаграму пакетів (Package Diagram);
o UML діаграму взаємодії (Interaction Overview Diagram);
o UML діаграму діяльності (Activity Diagram);
o UML діаграму станів (State Diagram).
     Код web-застосунку необхідно завантажити на GitHub перез захистом роботи.


3 ОПИС ВИКОНАНОЇ РОБОТИ

     У ході виконання лабораторної роботи було розроблено front-end частину програмної системи у вигляді односторінкового web-застосунку (Single Page Application). Клієнтська частина системи реалізована з використанням бібліотеки React та мови програмування TypeScript.
     Web-застосунок забезпечує взаємодію користувачів із серверною частиною системи через REST API та підтримує окремі інтерфейси для звичайних користувачів і адміністраторів відповідно до ролей у системі.
     Під час розробки було використано сучасний стек технологій, зокрема:
• React - для побудови компонентного інтерфейсу;
• TypeScript - для статичної типізації та підвищення надійності коду;
• TanStack Router - для реалізації маршрутизації;
• Zustand - для керування глобальним станом застосунку;
• React Query - для роботи з асинхронними запитами та кешування даних;
• shadcn/ui - для створення уніфікованого інтерфейсу користувача.

     Архітектура застосунку побудована за модульним принципом, де окремі компоненти відповідають за конкретні функції системи. Такий підхід спрощує підтримку програмного забезпечення, повторне використання компонентів та подальше масштабування системи.
     Front-end частина системи складається зі сторінок, UI-компонентів, hooks та модулів взаємодії із серверною частиною системи.
     Для навігації між сторінками застосовується TanStack Router, який забезпечує підтримку динамічних маршрутів та передачу параметрів між сторінками. Дані із серверної частини отримуються через React Query, після чого передаються дочірнім компонентам для подальшого відображення.
     
     Приклад сторінки відображення інформації про транспортний засіб наведено у коді в додатку В.1. Компонент CarDetailsPage отримує параметр VIN-коду із маршруту, виконує HTTP-запит до серверної частини системи за допомогою React Query та передає отримані дані дочірнім компонентам. Компоненти CarInfoCards, ReportSection та EventsSection відповідають за відображення окремих частин інформації про транспортний засіб. Такий підхід дозволяє розділити логіку інтерфейсу на незалежні модулі та спрощує повторне використання компонентів у різних частинах системи.
     Для взаємодії із серверною частиною системи використовується REST API. Отримання та оновлення даних реалізовано за допомогою бібліотеки React Query, яка забезпечує асинхронне виконання HTTP-запитів, кешування результатів та автоматичне оновлення даних.
     Одним із прийнятих інженерних рішень стало використання React Query замість ручного керування станом асинхронних запитів. Це дозволило:
• зменшити кількість повторних HTTP-запитів;
• реалізувати кешування отриманих даних;
• автоматично оновлювати інформацію після змін;
• спростити обробку станів завантаження та помилок.
     
     Назва інструменту та версія: Gemini 3.1 Pro..
     Мета використання: отримання перекладів елементів інтерфейсу українською та англійською мовами для подальшої реалізації системи локалізації через i18n.
     Внесок автора: виконано перевірку отриманих перекладів на коректність, внесено необхідні зміни та інтегровано переклади у програмний код web-застосунку.
     Однією з вимог лабораторної роботи була підтримка багатомовності web-застосунку. Для реалізації локалізації було використано бібліотеку i18next та модуль react-i18next.
     Система підтримує українську та англійську мови інтерфейсу. Обрана користувачем мова зберігається у локальному сховищі браузера, що дозволяє автоматично відновлювати мовні налаштування після повторного відкриття застосунку. Приклад ініціалізації системи локалізації наведено у коді нижче:

     Для адміністрування системи було реалізовано окремий адміністративний інтерфейс, який забезпечує управління користувачами, транспортними засобами, модерацію контенту та адміністрування бази даних.
     У системі реалізовано рольову модель доступу, відповідно до якої адміністративні функції розподіляються між декількома типами адміністраторів:

• Moderator - модератор системи;
• Database Administrator - адміністратор бази даних;
• Super Administrator - супер-адміністратор системи.

     Кожна роль має окремий набір дозволених операцій, що забезпечує розмежування доступу та підвищує безпеку системи.
     Модератор системи відповідає за:
• блокування та розблокування користувачів;
• перевірку транспортних засобів;
• перегляд статистики верифікації;
• моніторинг активності користувачів.

     Адміністратор бази даних відповідає за:
• створення резервних копій бази даних;
• відновлення резервних копій;
• оптимізацію бази даних;
• перегляд статистики використання бази даних;
• управління резервними копіями.

     Супер-адміністратор має розширені права доступу та відповідає за:
• управління адміністраторами системи;
• пошук користувачів;
• зміну ролей користувачів;
• видалення користувачів.

     У лістингу 3.6 (ряд. 1–24) показано реалізацію логіки адміністративної панелі для роботи з базою даних. Для отримання інформації про резервні копії та статистику використання бази даних застосовуються React Query hooks useBackupsQuery та useDbAnalysisQuery, які виконують асинхронні HTTP-запити до серверної частини системи та автоматично оновлюють інтерфейс після отримання нових даних.
     Після успішного виконання адміністративних операцій система автоматично відображає інформаційні повідомлення користувачу за допомогою механізму toast-сповіщень. Це дозволяє покращити взаємодію адміністратора із системою та забезпечити миттєвий зворотний зв’язок щодо результату виконаної операції.
     Також у панелі адміністрування реалізовано отримання статистики використання бази даних, перегляд списку резервних копій та виконання критичних операцій через модальні діалогові вікна підтвердження. Використання таких компонентів дозволяє зменшити ризик випадкового видалення або відновлення даних та підвищує надійність роботи адміністративної частини системи.
