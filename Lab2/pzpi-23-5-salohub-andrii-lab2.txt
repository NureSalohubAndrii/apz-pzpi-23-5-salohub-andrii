2 ЗАВДАННЯ

     На цій лабораторній роботі потрібно розробити мобільний програмний застосунок для будь-якої поширеної на сьогодні мобільної платформи. Мобільний застосунок повинен бути частиною системи і повинен взаємодіяти з нею. Для реалізації програмного застосунку можна використовувати технології для реалізації програмного забезпечення для мобільних платформ, вказані лектором, а саме Kotlin для Android та Swift для iOS. Звіт повинен містити опис прийнятих інженерних рішень. У ньому повинна бути показана будова мобільного застосунку та його взаємодія з іншими частинами системи.

Вимоги до оформлення

Звіт повинен містити:
- UML діаграму прецедентів (Use Case Diagram);
- UML діаграму компонент (Component Diagram).
- Не менше ніж дві діаграми, на вибір, із вказаних:
o ER-модель даних (Entity–Relationship Model) мобільної платформи;
o UML діаграму пакетів (Package Diagram);
o UML діаграму взаємодії (Interaction Overview Diagram);
o UML діаграму діяльності (Activity Diagram);
o UML діаграму станів (State Diagram).
     Код мобільного застосунку необхідно завантажити на GitHub перез захистом роботи.


3 ОПИС ВИКОНАНОЇ РОБОТИ

     У ході виконання лабораторної роботи було розроблено мобільний застосунок для платформи iOS із використанням мови програмування Swift та фреймворку SwiftUI. Застосунок є клієнтською частиною інформаційної системи для перегляду історії транспортних засобів за VIN-кодом.
     Архітектура програмного забезпечення побудована відповідно до шаблону MVVM (Model-View-ViewModel). Такий підхід дозволяє розділити логіку інтерфейсу користувача, бізнес-логіку та моделі даних, що спрощує підтримку та масштабування застосунку.
     Основними компонентами системи є:
- Model - структури даних, що описують користувачів, автомобілі, звіти та події;
- View - екрани користувацького інтерфейсу, реалізовані за допомогою SwiftUI;
- ViewModel - компоненти, що відповідають за отримання даних із серверної частини, обробку стану та взаємодію між View і Model.

     Стартовою точкою мобільного застосунку є структура CarHistoryApp (ряд. 1-11).
1  import SwiftUI
2  import SwiftData
4  @main
5  struct CarHistoryApp: App {
6      var body: some Scene {
7          WindowGroup {
8              RootView()
9          }
10     }
11 }

     У цьому коді показано головну структуру застосунку. Після запуску застосунок відображає кореневий компонент RootView, який відповідає за перевірку стану авторизації користувача та навігацію між екранами.
     Для реалізації бізнес-логіки застосунку було використано ViewModel-компоненти. Одним із основних є AuthViewModel, який відповідає за авторизацію користувачів, реєстрацію, оновлення JWT-токенів та отримання інформації про поточного користувача.
	У AuthViewModel (ряд. 1-13) показано використання механізму ObservableObject, який дозволяє автоматично оновлювати користувацький інтерфейс при зміні стану ViewModel. Властивості, позначені через @Published, автоматично повідомляють SwiftUI про необхідність оновлення інтерфейсу.
     Для збереження JWT-токена використовується механізм @AppStorage, який дозволяє зберігати дані локально на пристрої.
1  class AuthViewModel: ObservableObject {
2      @Published var isAuthenticated: Bool = false
3      @Published var currentUser: User? = nil
4  
5      @Published var isLoading: Bool = false
6      @Published var errorMessage: String = ""
7  
8      @AppStorage("jwt_token") var token: String = ""
9  
10     init() {
11         checkAuth()
12     }
13 }

     Мобільний застосунок взаємодіє із серверною частиною через REST API. Для виконання HTTP-запитів використовується URLSession. У коді функції login (ряд. 1-18) показано процес формування HTTP POST-запиту до серверної частини системи. Дані користувача передаються у форматі JSON, після чого відповідь сервера декодується у відповідні моделі даних.
1  func login(email: String, pass: String) {
2      isLoading = true
4      let url = URL(string: "\(Constants.baseURL)/auth/login")!
5      let body: [String: Any] = [
6          "email": email,
7          "password": pass
8      ]
9  
10     performRequest(
11         url: url,
12         body: body,
13         responseType: ApiResponse<AuthData>.self
14     ) { result in
15         DispatchQueue.main.async {
16             self.isLoading = false
17         }
18     }
19 }
     Для створення інтерфейсу користувача використано декларативний підхід SwiftUI. У коді нижче (ряд. 1-20) реалізовано форму входу користувача. Для збереження локального стану використовується @State, а для доступу до ViewModel - @EnvironmentObject. Після натискання кнопки викликається метод login, який виконує HTTP-запит до серверної частини системи.
1  struct LoginView: View {
2      @EnvironmentObject var viewModel: AuthViewModel
3  
4      @State private var email = ""
5      @State private var password = ""

18                 Text("Log In")
19             }
20         }

22 }

     Оскільки мобільний застосунок взаємодіє із серверною частиною системи через REST API, для виконання HTTP-запитів використовується асинхронна модель обробки даних. Такий підхід дозволяє уникнути блокування головного потоку застосунку та забезпечує плавну роботу користувацького інтерфейсу під час отримання інформації із сервера.
     Назва інструменту та версія: Gemini 3.1 Pro.
     Мета використання: отримати розуміння як реалізуються асинхронні запити в SwiftUI.
     Внесок автора: проаналізував відповідь, і після цього застосував отримання знання в реалізації асинхронних запитів і проєкті.
     Для реалізації асинхронної взаємодії використовується клас URLSession та метод dataTask, який виконує мережеві запити у фоновому потоці.
     У коді наведеному в додатку В.1 показано приклад асинхронного виконання HTTP-запиту для отримання інформації про транспортний засіб за VIN-кодом. Метод dataTask виконує мережеву операцію у фоновому режимі, що дозволяє не блокувати роботу інтерфейсу користувача.
     Після отримання відповіді від сервера використовується DispatchQueue.main.async, який забезпечує оновлення стану інтерфейсу у головному потоці застосунку. Отримані дані декодуються із формату JSON у відповідні моделі даних за допомогою JSONDecoder. Також у процесі обробки відповіді реалізовано механізми перевірки помилок мережевого з’єднання, відсутності даних та помилок декодування відповіді сервера.

     У ході виконання лабораторної роботи було розроблено мобільний програмний застосунок для сучасної мобільної платформи, який є частиною загальної інформаційної системи та взаємодіє з її серверною частиною. Під час реалізації було застосовано сучасні технології мобільної розробки, а також враховано принципи зручності використання, модульності та масштабованості програмного забезпечення.

Також було описано прийняті інженерні рішення щодо архітектури застосунку, організації коду, обробки даних та забезпечення взаємодії між компонентами системи.
     Отримані результати дозволили закріпити практичні навички розробки мобільних застосунків, роботи з клієнт-серверною архітектурою та інтеграції мобільного програмного забезпечення з іншими частинами системи.
